# Embedded Atlas

> **학습 사이트 바로가기: [https://hundong2.github.io/embedded/](https://hundong2.github.io/embedded/)**

전류의 경로를 직접 보고 조작하며 배우는 한국어 전기·전자·임베디드 기초 학습실입니다.

## 무엇을 배울 수 있나요?

첫 화면의 **START HERE**에서 전원의 +·−단자를 모두 그린 회로로 전압 차이 → 스위치와 닫힌 고리 → GND와 귀환선을 먼저 배웁니다. 스위치를 닫아도 귀환선을 끊으면 전류가 멈추는 것을 직접 확인할 수 있습니다. 이후 풀업 회로에서도 생략하지 않은 전원 귀환선과 GPIO 입력 전압·저항 양단 전압을 비교합니다.

- **전류의 경로:** 열린 회로와 닫힌 회로, 스위치 위치, 전원 극성, GND 기준, 관습적 전류와 전자 이동.
- **풀업·풀다운:** 스위치 전후 GPIO 전압과 논리 상태, 부동 입력, 저항 전류와 소비 전력.
- **저항과 RC:** 직렬 분압·병렬 분류, 충전·방전, 시정수, 저장 에너지.
- **디지털과 주변장치:** 논리 임계값·게이트, PWM 듀티, ADC 양자화, I²C·SPI·UART 타이밍, 비트·레지스터.
- **연결된 학습 노트:** 전기 기초 → 전자부품 → 디지털 → MCU 구조 → 인터페이스 → 펌웨어·운영체제. 각 노트에 목표, 선수 개념, 그림, 실험, 설명, 오개념, 퀴즈와 출처가 있습니다.

학습 완료 기록은 `localStorage`에 저장되며 계정이나 서버가 필요하지 않습니다. 기록은 브라우저와 기기 사이에 동기화되지 않습니다.

## 로컬 실행

Node.js 22.12 이상에서:

```sh
npm ci
npm run dev
```

개발 주소는 http://127.0.0.1:5173/embedded/ 입니다.

```sh
npm run check
npx playwright install chromium
npm run test:e2e
npm run preview
```

`check`는 지식 그래프 생성, 콘텐츠·출처 계약 검증, 수치 모델/계약 회귀 테스트, 프로덕션 빌드를 실행합니다. 브라우저 테스트는 빌드 결과의 `/embedded/` 경로에서 데스크톱과 모바일 학습 여정을 확인합니다.

## GitHub Pages

`.github/workflows/pages.yml`은 `main` push와 수동 실행 시 검증을 통과한 `dist/`만 Pages에 배포합니다. PR에서는 같은 검증을 실행하고 배포하지 않습니다. 저장소 **Settings → Pages → Source → GitHub Actions**를 사용합니다.

프로젝트 사이트의 기본 경로는 `/embedded/`입니다. 다른 이름의 저장소에 배포할 때는 `VITE_BASE_PATH=/다른이름/ npm run build`로 지정하거나 `vite.config.js`의 기본값을 바꾸세요. 루트 사용자 사이트에는 `/`를 사용합니다. 모든 학습 링크는 해시 라우팅을 사용하므로 새로고침에 서버 재작성 설정이 필요하지 않습니다.

## 출처와 수록 범위

[임베디드 레시피](https://recipes.tistory.com/)의 공개 sitemap, 강의실 전체맵, 카테고리와 내부 링크로 발견한 글을 조사합니다. 원문·그림은 복제하지 않고 독창적인 설명과 그림을 원문 링크에 연결합니다.

- [공개 인벤토리](public/data/source-manifest.json): 발견 URL, 접근/검토 상태, 학습 노트 매핑, 제외 이유 및 외부 링크.
- [출처 감사 보고서](docs/source-audit.md): 실제 집계, 확인 방법과 확인하지 못한 범위.
- 사이트의 **출처 · 안내**: 원문 검색과 학습 노트 연결을 확인하는 화면.

‘매핑’은 해당 주제가 학습 자료에 연결된다는 뜻입니다. 원문 전체의 모든 세부 내용·실습 환경·외부 연결 문서를 재현하거나 완전 검증했다는 뜻은 아닙니다. 비공개/삭제 글과 외부 사이트의 무한 재귀 수집도 포함하지 않습니다. 확인 상태는 숨기지 않고 인벤토리에 공개합니다.

출처를 갱신하려면:

```sh
npm run sources:sync
npm run check
```

재수집으로 새 글이 생기면 `pending-lesson` 상태를 검토하고 노트를 추가하세요. 원문 캐시는 `.cache/`에 저장되고 Git에서 제외됩니다. 크롤러 옵션과 검토 기록 방법은 [출처 감사 보고서](docs/source-audit.md)를 참고하세요.

## 유지보수와 AI 작업 하네스

- [AGENTS.md](AGENTS.md): 에이전트 역할, 파일 소유권, 물리 불변식과 완료 조건.
- [엔지니어링 문서](docs/engineering.md): 데이터 계약, 출처 추적, 테스트·CI와 재현 방법.
- [대화형 구조도](https://hundong2.github.io/embedded/architecture.html): Archify로 검증한 콘텐츠·모델·UI·배포 구조.
- [지식 그래프](public/data/knowledge-graph.json): 범주와 학습 노트, 선수 개념의 관계. 생성 결과와 실제 콘텐츠가 어긋나면 검증에서 실패합니다.
- `tests/physics.test.mjs`: 전류 보존·접지 불변성·풀 입력 진리표·RC·ADC·통신 타이밍의 수치 경계.
- `tests/content.test.mjs`: 잘못된 출처 매핑, 순환 선수 관계, 잘못된 퀴즈와 그래프를 실제로 주입하여 차단되는지 확인.
- `tests/e2e/`: 풀업/풀다운 실험, 9개 실험, 검색·퀴즈·진도 저장, 모바일 탐색과 reduced motion.

새 노트는 `src/data/lessons.js`의 계약을 따르세요. 새 계산은 DOM과 분리된 `src/sim/models.js`에 추가하고, 물리 가정·검증 가능한 수치 결과를 먼저 명시하세요. 런타임 LLM 호출이나 비밀키는 사용하지 않습니다.

## 교육 모델의 한계

이 사이트는 범용 회로 해석기나 실제 MCU 에뮬레이터가 아닙니다. 선형 저항·이상 전원·이상 스위치와 지정된 회로의 해석식을 사용합니다. GPIO 입력은 기본 누설 0 A이며 풀 실험에서는 0–20 µA의 등가 누설을 추가할 수 있습니다. 임계값은 0.3/0.7 × VCC 예시입니다. RC의 ESR·누설, ADC의 잡음·오프셋, 실제 버스의 상승/하강시간 등은 생략됩니다. 그림의 점 이동 속도는 실제 전하 속도가 아닙니다. 제품의 전기적 한계와 실제 동작은 해당 데이터시트에서 확인하세요.
